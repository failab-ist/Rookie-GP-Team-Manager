## 1. 개요

세 컵을 합쳐 16전이다. 신규 계정이 첫날부터 정규 주간 리그가 시작되기 전까지 치르는 NPC 전용 콘텐츠다(GDD:836~849). 기준선은 O-120의 루키 챔피언십 6전이다(GDD:836~862). 16전 구조는 기준을 대신하는 안이 아니라 비교안이다.

경기 배분은 두 안을 적는다.

- **16-A (기본 가안, 5/5/6):** 루키 컵 5전, 챌린지 컵 5전, 루키 그랑프리 6전.
- **16-B (대안, 4/6/6):** 루키 컵 4전, 챌린지 컵 6전, 루키 그랑프리 6전. 합은 16이다. 루키 컵을 짧게 해 첫날 대기 시간을 줄이는 방향이다. 보상과 시간은 16-A와 따로 계산한다(F4 예시 3, 5.3절).

시간 기준은 AG-L004(C, 실측 후 결정)다(`.studio/decisions.jsonl:2`). 그래서 경기 길이는 시간표 A(3~5분)와 시간표 B(60~75초) 두 가지를 함께 쓴다(5절 F3).

코어 프로토에는 루키 경제를 구현하지 않는다(GDD:898). 이 문서는 구현 범위를 정하지 않는다.

## 3. 규칙

### 3.1 공통 필수 규칙

1. 이 구조의 모든 경기는 티켓을 쓰지 않는다. 루키 컵(가안)의 경기는 일반 티켓과 별도로 센다(GDD:847).
2. 보상은 계정당 1회만 준다. 지급 플래그가 켜진 경기는 다시 주지 않는다. 재도전은 무보상이다(4.3절).
3. 상대는 모두 NPC다. 화면과 결과 카드에 NPC 표시를 붙인다(GDD:845). 라이벌 NPC도 같이 표시한다(3.5절).
4. 이 구조의 결과는 정규 6주 결승 자격과 무관하다. 주간 리그 성적과도 무관하다(GDD:849, GDD:894).
5. 모든 경기는 10대 NPC 레이스다(SPEC:35, GDD:280). 플레이어 레이서 1대와 NPC 9대가 함께 달린다(GDD:320). 1:1 형식 여부는 이 문서에서 정하지 않고 RACE_DRAFT Q-1로 넘긴다.
6. 결과를 조작하지 않는다. 특정 승패를 강요하지 않는다(GDD:840). 같은 시드로 다시 계산하는 것은 조작이 아니다.
7. 경기 설명은 시뮬레이터 로그에서만 만든다. 로그 없는 해설을 붙이지 않는다(GDD:899).

### 3.2 컵별 해금

프로토 범위(레이서 3명, 차량 2종, 트랙 3종, SPEC:48) 안에서만 해금한다. 해금 대상은 아래 표의 항목뿐이다. 레이서 ④, 차량 ③, 트랙 ④는 만들지 않는다. 훈련, 카드, 뽑기는 넣지 않는다.

| 컵 | 안 1 조건 (순차 해금, 가안) | 안 1 해금 대상 | 안 2 조건 (차량 먼저, 가안) | 안 2 해금 대상 |
|---|---|---|---|---|
| 루키 컵(가안) | 시작 시 열림 | 레이서 ①, 차량 ①, 트랙 ① | 시작 시 열림 | 레이서 ①, 차량 ①, 트랙 ① |
| 챌린지 컵(가안) | 루키 컵 완주 | 레이서 ②, 트랙 ② | 루키 컵 완주 | 차량 ② |
| 루키 그랑프리(가안) | 챌린지 컵 완주 | 레이서 ③, 차량 ②, 트랙 ③ | 챌린지 컵 완주 | 레이서 ②, 레이서 ③, 트랙 ②, 트랙 ③ |

- 안 1의 해금 대상을 전부 합하면 레이서 ①②③, 차량 ①②, 트랙 ①②③이다. 안 2도 같다. 두 안 모두 프로토 범위를 넘지 않는다.
- 안 2에서 레이서 ②와 트랙 ②는 루키 그랑프리(가안) 완주 조건으로 열린다. 챌린지 컵(가안)에서는 차량 ②만 열린다.
- "완주"는 3.3절의 진행 조건에 따라 다르다. 여기서는 완주 조건 안 1을 예로 쓴다.
- 해금은 계정당 1회 기록이다. 재도전으로 다시 열지 않는다.

### 3.3 진행 조건 선택지

컵이 끝난 뒤 다음 컵을 여는 조건이다. 세 안 중 하나를 골라야 하며, 아직 고르지 않았다(R-5).

| 안 | 조건 (가안) | 조건에 막혔을 때 |
|---|---|---|
| 안 1. 완주만 하면 됨 | 컵의 모든 경기에 결과가 기록되면 다음 컵이 열린다. 리타이어도 결과가 기록되면 통과한다(0점, F1). | 서버 결과 기록이 실패하면 그 경기는 기록될 때까지 k가 오르지 않는다. 같은 시드로 재시도한다. 결과를 바꿔 쓰지 않는다. |
| 안 2. 순위 조건 (가안) | 컵 종료 시 F2 컵 순위가 상위 5위 이내(10대 중)이면 다음 컵이 열린다. | 6위 이하이면 상태가 조건 미달이 된다. 같은 컵을 재도전한다. 재도전은 무보상이며, 기록은 순위 조건 계산에만 쓴다. 재도전 횟수 제한은 없어서 영구 정지되지 않는다. |
| 안 3. 하루 개방 수 제한 (가안: 하루 1컵) | 하루에 새로 열 수 있는 컵은 1개다. 완주 조건은 안 1과 같다. | 같은 날 이미 한 컵을 열었으면 다음 컵은 잠김을 유지한다. 다음 날 00:00에 열린다(6절 2번). |

- 안 2에서 루키 그랑프리(가안)에는 순위 조건을 적용하지 않는다(가안). 다음 컵이 없어서 열 대상이 없기 때문이다. 과정 종료는 루키 그랑프리 완주로 정한다. 마지막 컵에도 순위 조건을 적용하려면 R-5에서 고른다.

### 3.4 보상 총량 선택지

보상 분배 방식은 F4(5절)다. 여기서는 총량과 컵별 가중치만 고른다. 총량은 디렉터 결정을 기다린다(R-3).

컵별 가중치 w (가안, 16-A 기준)

| 컵 | 경기 수 N | 경기당 w (가안) | 컵 합계 N × w |
|---|---|---|---|
| 루키 컵(가안) | 5 | 1 | 5 |
| 챌린지 컵(가안) | 5 | 2 | 10 |
| 루키 그랑프리(가안) | 6 | 3 | 18 |
| 합계 Σw | 16 | | 33 |

16-B를 고르면 Σw = 4 × 1 + 6 × 2 + 6 × 3 = 34가 된다. 계산은 F4 예시 3에 있다.

총량 선택지

| A. O-120 총량 유지 | 15,000~20,000 (GDD:856) | 30~40 (GDD:857) | 6전 가안 총량을 16전에 그대로 나눈다 | 기존 가안과 같다 | 16전으로 늘면 경기당 보상이 줄어든다 | 가안 |

- 머니와 스패너는 따로 계산한다. 서로 바꾸지 않는다(SPEC:38).

### 3.5 라이벌 NPC 안

라이벌도 NPC이며 NPC 표시를 붙인다. 난이도는 전력 값으로만 조정한다. 레이서 외형이나 이름으로 난이도를 주지 않는다.

| 안 | 내용 | 장점 | 리스크 |
|---|---|---|---|
| 1. 고정 라이벌 | 세 컵 내내 같은 NPC 1명이 라이벌이다 (NPC 9대 중 1명) | 대결 기억이 쌓인다 | 한 명의 전력 값이 세 컵 전체 난이도를 정한다 |
| 2. 컵마다 바뀌는 라이벌 | 컵마다 다른 NPC 1명이 라이벌이다 | 컵마다 새 상대가 생긴다 | 대결 기억이 끊긴다 |
| 3. 라이벌 없음 | 라이벌 표시 없이 NPC 9대만 나온다 | 가장 단순하다 | 돌아올 이유가 약하다 (AG-L003 A의 단점과 같은 문제) |

- 라이벌 전력 차의 범위 −5% ~ +5%(가안)는 실측 전에 고른 임시 값이다. 근거 문장이 없다. 실측과 디렉터 결정 전에는 판정 기준으로 쓰지 않는다. 범위를 넓히면 라이벌 전력 차가 커져 특정 레이서가 거의 항상 이기는 편중이 생길 수 있다. 이 점은 실측으로 확인한다.
- 라이벌 NPC는 플레이어 레이서와 같은 캐릭터가 될 수 없다(6절 6번).
- 라이벌 선택은 R-7이다.

## 5. 공식

### F1. 경기 포인트 (가안)

| 항목 | 내용 |
|---|---|
| 이름 | 경기 포인트 `p` |
| 식 | 완주한 경우 `p = 11 − pos`. 완주하지 못한 경우 `p = 0` |
| 변수 | `pos`: 경기 최종 순위. 정수 1~10. `p`: 경기 포인트. 정수 0~10 |
| 범위 | `pos` 1~10. 완주하면 `p` 1~10, 완주하지 못하면 0(가안) |
| 출처 | GDD:279의 예시(1위 10점, 10위 1점). 완주하지 못하면 0점은 가안 |
| 계산 예시 | `pos = 8`이면 `p = 11 − 8 = 3`. `pos = 1`이면 `p = 10` |
| 퇴화 결과 | `pos`가 1~10 밖이면 입력 오류다. 포인트를 주지 않고 오류로 기록한다. 해당하는 값은 `pos = 0`, `pos = 11`, 소수(예: 2.5)다. 완주하지 못해 `p = 0`인 것은 정상 결과다 |

### F2. 컵 순위 (가안)

| 항목 | 내용 |
|---|---|
| 이름 | 컵 순위 |
| 식 | `P_cup = Σ p_j` (j는 1부터 k까지, 컵 안에서 완료한 경기). 큰 값이 위다 |
| 변수 | `P_cup`: 컵 누적 경기 포인트. `p_j`: j번째 경기 포인트(F1). `k`: 완료한 경기 수 |
| 범위 | `P_cup`은 0 이상의 정수. `k`는 0 이상 N 이하 |
| 동점 처리 (가안, O-106) | 동점이면 마지막 경기 순위가 더 좋은 쪽이 위다. 이 방향은 R-6에서 디렉터가 정한다 |
| 비교 방식 (가안) | 같은 `k`끼리만 비교한다. 서로 다른 k의 순위는 같은 줄에 두지 않는다 |
| 계산 예시 | 한 컵 3전에서 `p = [10, 3, 8]`이면 `P_cup = 21` |
| 퇴화 결과 | `k = 0`이면 순위가 없다(표시 `–`). 동점이고 마지막 경기 순위까지 같으면 공동 순위로 기록하고, 보상 분배에는 쓰지 않는다(R-6 결정 전까지) |

### F4. 보상 분배 (가안, 반려 반영)

방식은 내림 후 큰 나머지 순으로 +1을 주는 최대 잉여 방식이다(가안).

| 항목 | 내용 |
|---|---|
| 이름 | 경기별 보상 분배 `b_i` |
| 식 | 이론 몫 `q_i = 총량 × w_i / Σw`. 정수 몫 `b_i = floor(q_i)`. 나머지 개수 `R = 총량 − Σb_i`. 소수부 `q_i − b_i`가 큰 경기부터 R개 경기에 +1 |
| 동률 처리 (가안) | 소수부가 같으면 번호가 큰 경기(뒤 경기)를 먼저 고른다. 근거: 결승에 가까울수록 보상이 커지는 흐름 |
| 변수 | `총량`: 머니 또는 스패너 총량(정수). `w_i`: 경기 i의 가중치(그 경기가 속한 컵의 w, 3.4절). `Σw`: 전체 경기의 w 합. `q_i`: 경기 i의 이론 몫. `b_i`: 경기 i의 정수 보상. `R`: 나눠 줄 나머지 개수 |
| 범위 | `총량`은 0 이상의 정수. `w_i`는 0 이상. `Σw > 0` |
| 출처 | 총량 범위는 GDD:856(머니), GDD:857(스패너) |

성질 (확인 가능한 것)

- 모든 `b_i ≥ 0`이다. 내림한 값은 0 이상이고, 더하는 것은 +1뿐이기 때문이다.
- `0 ≤ R < 경기 수`이다. `R`은 소수부의 합이고 각 소수부는 1보다 작다.
- 최종 합 `Σb_i`(+1 포함)는 정확히 `총량`이다.
- `w_i = 0`이면 `b_i = 0`이고 +1도 받지 않는다. 이유는 다음과 같다. `R`은 양수 소수부들의 합이고 각 소수부는 1보다 작다. 그래서 `R`은 양수 소수부를 가진 경기 수보다 항상 작다. 소수부가 0인 경기는 맨 뒤로 밀리므로 +1을 받을 차례가 오지 않는다.

예시 1 (검수 지적 사례, 동일 가중치, 16-A 구조)

- 총량 40(스패너, GDD:857 범위 안), 16경기, 모든 `w_i = 1`. `Σw = 16`.
- `q_i = 40 / 16 = 2.5`, `b_i = 2`. `Σb = 32`, `R = 8`.
- 모든 소수부가 0.5로 같다. 번호가 큰 9~16전이 +1을 받는다.
- 검산: 1~8전은 2 × 8 = 16, 9~16전은 3 × 8 = 24. 합계 16 + 24 = 40. 음수 0건.

예시 2 (컵 가중치가 다른 경우, 16-A, 가안 w 1/2/3)

- 총량 40(스패너). 루키 컵(가안) `w = 1`, 챌린지 컵(가안) `w = 2`, 루키 그랑프리(가안) `w = 3`.
- `Σw = 5×1 + 5×2 + 6×3 = 33`.
- 컵별 `q_i`, `b_i`, 소수부는 다음과 같다.
  - 루키 컵(가안) 1~5전: `q = 40/33 ≈ 1.212`, `b = 1`, 소수부 `7/33 ≈ 0.212`.
  - 챌린지 컵(가안) 6~10전: `q = 80/33 ≈ 2.424`, `b = 2`, 소수부 `14/33 ≈ 0.424`.
  - 루키 그랑프리(가안) 11~16전: `q = 120/33 ≈ 3.636`, `b = 3`, 소수부 `7/11 ≈ 0.636`.
- `Σb = 5×1 + 5×2 + 6×3 = 33`, `R = 40 − 33 = 7`.
- 소수부가 가장 큰 루키 그랑프리(가안) 6경기가 먼저 +1을 받는다(6개). 남은 1개는 다음으로 큰 소수부인 챌린지 컵(가안) 5경기 중 번호가 가장 큰 10전이 받는다.
- 결과: 루키 컵(가안) 1~5전은 1 × 5 = 5. 챌린지 컵(가안) 6~9전은 2 × 4 = 8, 10전은 3이므로 합계 11. 루키 그랑프리(가안) 11~16전은 4 × 6 = 24.
- 검산: 5 + 11 + 24 = 40. 음수 0건.

예시 3 (16-B 구조, 총량 40, 가안 w 1/2/3)

- 경기 배치는 루키 컵(가안) 1~4전(w 1), 챌린지 컵(가안) 5~10전(w 2), 루키 그랑프리(가안) 11~16전(w 3).
- `Σw = 4×1 + 6×2 + 6×3 = 34`.
- 컵별 `q_i`, `b_i`, 소수부는 다음과 같다.
  - 루키 컵(가안) 1~4전: `q = 40/34 ≈ 1.176`, `b = 1`, 소수부 `6/34 ≈ 0.176`.
  - 챌린지 컵(가안) 5~10전: `q = 80/34 ≈ 2.353`, `b = 2`, 소수부 `12/34 ≈ 0.353`.
  - 루키 그랑프리(가안) 11~16전: `q = 120/34 ≈ 3.529`, `b = 3`, 소수부 `18/34 ≈ 0.529`.
- `Σb = 4×1 + 6×2 + 6×3 = 34`, `R = 40 − 34 = 6`.
- 소수부가 가장 큰 루키 그랑프리(가안) 6경기가 6개의 +1을 모두 받는다. 그래서 11~16전은 각각 4를 받는다.
- 검산: 루키 컵(가안) 1~4전은 1 × 4 = 4. 챌린지 컵(가안) 5~10전은 2 × 6 = 12. 루키 그랑프리(가안) 11~16전은 4 × 6 = 24. 합계 4 + 12 + 24 = 40. 음수 0건.

퇴화 결과

- 총량 0이면 전 경기 0을 지급한다. 오류가 아니다.
- 총량이 경기 수보다 작으면 0을 받는 경기가 생긴다. 예를 들어 총량 10, 16경기, 동일 가중치이면 `q = 0.625`, `b = 0`, `R = 10`이다. 번호가 큰 10경기(7~16전)가 1을 받고, 1~6전은 0을 받는다. 이것은 정상 결과다.
- 총량이 음수이거나 정수가 아니면 입력 오류다. 지급하지 않고 오류로 기록한다.
- `w_i < 0`이면 입력 오류다. 지급하지 않는다.
- `Σw = 0`이면 0으로 나누지 않는다. 지급하지 않고 오류로 기록한다.
- 머니와 스패너는 따로 계산한다. 서로 바꾸거나 합치지 않는다(SPEC:38).

## 6. Edge case (예외 상황)

| 상황 | 결과 |
|---|---|
| 1. 컵 진행 중 이탈 | 이탈 전까지 기록된 경기는 유지한다. 보상 플래그가 켜진 경기는 다시 주지 않는다. 결과가 기록되지 않은 k번째 경기는 같은 시드로 처음부터 다시 달린다. 상태는 진행 중(k/N전)으로 남는다(4.3절) |
| 2. 00:00이 지나는 순간 경기가 진행 중 | 경기 시작 시각으로 날짜를 정한다. 00:00 이전에 시작한 경기는 전날에 귀속한다. 안 3의 하루 개방 한도는 귀속된 날짜로 센다(가안) |
| 3. 정규 리그 편성 뒤에도 컵을 끝내지 못함 | 두 체계는 독립이다. 정규 리그는 편성된 6경기를 정상 계산한다(GDD:322). 컵은 계속 진행할 수 있다. 티켓은 쓰지 않는다(GDD:847). 컵 결과는 정규 결승 자격과 무관하다(GDD:849) |
| 4. 재설치하거나 계정이 중복됨 | 보상 플래그와 진행 기록은 서버 계정 기준이다. 재설치 후 로그인하면 기록을 이어받고, 이미 켜진 플래그는 다시 주지 않는다. 계정이 두 개이면 계정마다 1회씩 지급한다. 같은 사람의 중복 계정을 막는 방법은 이 문서 범위 밖이다(R-8) |
| 5. 서버 지급 실패 | 지급 요청이 실패하면 해당 경기의 플래그를 켜지 않는다. 다시 시도할 때 지급한다. 플래그가 이미 켜져 있으면 다시 지급하지 않는다 |
| 6. 라이벌 NPC가 내 레이서와 같은 캐릭터 | 라이벌 슬롯에서 같은 캐릭터를 뺀다. 대신 전력 값이 가장 가까운 다른 NPC를 라이벌로 쓴다. NPC 표시는 그대로 붙인다(가안) |
| 7. F4 입력 오류 | 해당 컵의 보상 지급을 보류한다(0건 지급). 오류를 기록한다. 컵 진행은 계속된다. 입력을 고치면 같은 식으로 다시 계산해 지급한다 |
| 8. F1 입력 오류(`pos`가 범위 밖) | 그 경기에 포인트를 주지 않는다. 오류를 기록한다. 이 경기는 F2 누적에 넣지 않는다 |
| 9. 같은 순위가 두 대에 들어옴 | 입력 오류로 기록한다. 시뮬레이터 결과를 고쳐 쓰지 않는다(GDD:840) |
