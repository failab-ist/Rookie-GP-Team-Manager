## 1. 개요

레이스 중 화면이 어떤 장면을 보여 줄지 정하는 규칙이다. 시뮬레이터가 기록한 사건 로그를 입력으로 받아 장면 전환 우선순위, 최소 유지 시간, 내 차 고정을 정한다. 카메라 각도(O-007)는 이 문서에서 정하지 않으며, 연출 규칙은 각도와 무관하게 쓴다.

## 2. 플레이어 경험

- 기본 화면은 내 차 추적이다. 사건이 나면 관련 차를 잠시 보여 주고 다시 내 차로 돌아온다.
- 10대 중 추월, 접촉, 패시브 발동, 선두 변경이 화면에서 읽혀야 한다(`GAME_VISION.md:14`: 준비한 것이 레이스에서 보여야 한다).
- 순위표는 늘 보인다. 순위가 바뀌면 순위표에서 바로 알 수 있어야 한다.
- 플레이어는 "방금 순위가 왜 바뀌었나"에 답할 수 있어야 한다(측정 M-11, §9.2).
- 내 차를 계속 보고 싶으면 고정 버튼을 누른다(§3.4). 고정 중에는 자동 장면 전환이 멈춘다.
- 결과 화면은 내 차가 완주하면 한 번 나온다.
- 레이스 화면의 가독성이 최우선 통과 기준이다(`GAME_VISION.md:51`, `design_ssot/TECH_STACK.md:52`).

## 3. 규칙

### 3.1 각도와 연출 구분

1. 각도는 투영 방식이다. O-007의 탑다운, 3/4, 절충 중 무엇을 고를지가 각도다. 이 문서는 고르지 않는다.
2. 연출은 세 가지다. (a) 비출 차(어떤 차를 화면에 담을지), (b) 배율(줌), (c) 전환 시점(§3.2, §3.3).
3. 근거: 현재 P0 시험판 코드는 시점과 카메라 모드를 따로 둔다. 시점 `view`는 `iso`/`top` 두 값이고(`prototypes/p0-visual/src/RaceScene.ts:31`, 전환 `:95`), 카메라 모드 `camMode`는 `me`/`leader`/`all` 세 값이다(`:11`, `:32`, `:94`). 두 축이 코드에서도 분리돼 있다. 시점의 값 이름(`iso`, `top`)은 O-007의 세 안 이름과 같지 않다.
4. 연출 규칙(§3.2–§3.5)은 각도와 무관하게 쓴다. 각도별로 값이 달라야 하는지는 Q-11.
5. 이 문서는 O-007을 닫거나 확정하지 않는다.

### 3.2 화면 종류 표

우선순위 선택지:
- A안(고정 순위): 표의 우선순위 값을 그대로 쓴다.
- B안(내 차 관련 가중): 우선순위 = A안 값 + 3(내 차가 관련 차 목록에 있을 때만). 가중치 3은 가안이다. 출발 그리드와 결과는 가중하지 않는다.
- 우선순위가 같으면 §5.2 순서(사건 시각이 이른 것, 그다음 대표 차 번호가 낮은 것)로 고른다.

| 종류 | 등장 조건(로그 사건) | 우선순위 (A안 / B안) | 최소 유지 시간 (가안) | 끝나는 조건 | 최대 유지 시간 (가안) |
|---|---|---|---|---|---|
| 출발 그리드 | 로그의 출발 사건. 장면 시작 = 0 이상의 값 중 큰 값(출발 시각 − 미리 당김) | A안 8 (동점, 아래 충돌 참조) / B안 8(가중 없음) | 3.0 s | 출발 시각에 도달 | 4.0 s |
| 접촉 | 로그의 접촉 사건 | A안 7 / B안 7 또는 10 | 1.5 s | 관련 두 차의 시간 차가 경합 간격보다 커짐 | 3.0 s |
| 패시브 발동 | 로그의 패시브 발동 사건(원인 칸은 O-004 미정) | A안 6 / B안 6 또는 9 | 1.5 s | 발동 차와 바로 앞 · 뒤 차의 시간 차가 경합 간격보다 커짐 | 2.5 s |

| 결과 | 내 차 완주(선택지: 마지막 차 완주, Q-19) | 종료 상태. 우선순위 비교 대상이 아님 | 해당 없음(종료 상태) | 없음 | 없음 |

- 충돌(우선순위 동점): A안에서 출발 그리드와 마지막 랩 · 결승선이 모두 8이다. §5.1은 엄격한 대소 비교이므로 두 장면은 서로 끼어들지 못한다. 출발 그리드는 출발 시각에만 나오고 마지막 랩은 레이스 후반에 나오므로 실제로 겹칠 가능성은 낮다. 그래도 값을 달리할지는 USER가 정한다. §5.1의 최상위 장면 선택지(Q-27)와 함께 정한다.
- '전체' 축소 화면은 이 표에 없다. AG-L005 결정 대기(Q-12).
- 최소 · 최대 유지 시간 값은 §8과 같다. 시간 기준이 틱이면 초를 틱으로 바꿔 쓴다.

### 3.3 전환 세 종류

세 종류는 판정식이 서로 다르다. 같은 조건으로 묶지 않는다.

1. 끼어들기: 장면을 재생하는 중에 우선순위가 더 높은 요청이 온다. 판정식은 §5.1.
2. 복귀: 현재 장면이 끝난다. 판정식은 §4의 복귀 조건과 §5.2(대상 선택).
3. 사용자 조작: 고정 버튼을 누른다. 판정식이 없다. 최소 유지 시간과 우선순위를 보지 않고 즉시 전환한다(§4 고정 켬 · 끔).

| 안 | 동작 | 장점 | 리스크 | 상태 |

추천 이유(A안):
- 플레이어 경험 쪽 근거: 고정 상태가 켜짐과 꺼짐 두 가지뿐이라 설명과 학습이 가장 쉽다. B안은 풀리는 시점을 맞혀야 하고, C안은 허용 규칙을 따로 배워야 한다.
- 측정 쪽 보조 근거: A안만 조건 Y(§9.2)에서 자동 전환을 0으로 둘 수 있다. 측정 편의는 보조 근거다. 플레이어 경험이 같다면 측정 편의를 추천 근거로 쓴다.
- 일시 고정 시간(B안) 가안은 3.0 s(§8). 고정 방식 결정은 Q-25.

## 4. 상태와 전이

| 상태 | 들어오는 조건 | 나가는 조건 |
|---|---|---|
| 기본 화면(내 차 추적) | 재생 시작. 장면이 끝났고 복귀 대상이 없음(§5.2). 고정 끔 | 끼어들기 허용(§5.1). 고정 켬. 결과 |
| 장면 k 재생 | 끼어들기 허용으로 요청 j의 장면이 시작됨. 또는 복귀 대상으로 선택됨(§5.2) | 복귀 조건(아래). 고정 켬. 결과 |
| 내 차 고정 | 고정 켬(어느 상태에서든) | 고정 끔(기본 화면으로). 내 차 완주(결과로) |
| 결과 | 내 차 완주(Q-19) | 없음(종료) |

전이 규칙(가안)
- 끼어들기: 장면 k에서 장면 j로 바뀐다. §5.1이 참일 때만 일어난다.
- 복귀: 다음 둘 중 하나이면 복귀한다. (a) 끝나는 조건이 충족되고 장면 경과 시간이 최소 유지 시간 이상이다. (b) 장면 경과 시간이 최대 유지 시간 이상이다.
  - 끝나는 조건이 최소 유지 시간 전에 충족되면, 최소 유지 시간이 찰 때까지 그 장면을 유지한다.
  - 복귀 조건에는 우선순위 비교가 없다. 현재 장면보다 우선순위가 낮은 요청이 남아 있어도 복귀는 일어난다. 그 요청이 유효 시간 안에 있으면 §5.2에 따라 다음 장면이 된다. 없으면 기본 화면으로 간다.
  - 최대 유지 시간이 최소 유지 시간보다 짧은 설정은 입력 오류다(§5 공통).
- 고정 켬: 어느 상태에서든 즉시 고정 상태가 된다. 재생 중인 장면은 끊는다. 최소 유지 시간과 우선순위를 보지 않는다. 고정 중에 온 사건은 §6을 따른다.
- 고정 끔: 즉시 기본 화면으로 간다. 경과 시간을 0부터 다시 잰다. 유효 시간 안의 요청은 다음 틱에 §5.1로 다시 판정한다. 기본 화면의 우선순위는 0이고 경과 조건을 생략한다.
- 결과: 내 차가 완주하면 고정 여부와 관계없이 결과 상태가 된다. 최소 유지 시간과 우선순위를 보지 않는다. 나가는 조건은 없다.

## 5. 공식

### 5.1 끼어들기 허용 (가안)

```text
허용 = (요청 우선순위 > 현재 우선순위) 그리고 (장면 경과 시간 ≥ 최소 유지 시간)
  기본 화면에서는 현재 우선순위 = 0이고, 두 번째 조건을 생략한다.
```

| 변수 | 뜻 | 범위 | 출처 / 가안 |
|---|---|---|---|
| 요청 우선순위 | 끼어들려는 장면의 우선순위 | 정수 0~11(B안 가중 포함) | §3.2 가안 |
| 현재 우선순위 | 지금 재생 중인 장면의 우선순위 | 정수 0~11. 기본 화면은 0 | §3.2 가안 |
| 장면 경과 시간 | 장면이 시작한 뒤 흐른 시간(초) | 0 이상 | §8 시간 기준 |
| 최소 유지 시간 | 장면이 최소한 유지되는 시간(초) | 하한 0.5 s(§5 공통) | §3.2 가안 |

- 결과 범위: 허용은 참 또는 거짓이다.
- 계산 예시: 현재 장면은 추월(우선순위 5, 최소 유지 시간 1.5 s)이다. 장면이 시작된 뒤 1.0 s에 접촉 요청(우선순위 7)이 온다.
  - 1.0 s 시점: 7 > 5는 참이고 1.0 ≥ 1.5는 거짓이므로 허용되지 않는다. 요청은 유효 시간(1.0 s) 동안 남는다.
  - 1.5 s 시점: 7 > 5 참, 1.5 ≥ 1.5 참이므로 허용된다. 요청 유효 여부는 1.5 − 1.0 = 0.5 ≤ 1.0이므로 유효하다. 접촉 장면으로 바뀐다.
- 퇴화 결과:
  - 요청 우선순위 = 현재 우선순위: 거짓. 같은 우선순위끼리는 끼어들지 않는다.
  - 최소 유지 시간 = 0: 하한 0.5 s를 적용한다(§8). 0을 그대로 쓰면 매 틱 전환이 가능해진다.
  - 우선순위나 경과 시간이 음수: 입력 오류. 장면을 시작하지 않고 기록에 "입력 오류"를 남긴다.
- 선택지: 최상위 장면(A안 기준 우선순위 8: 출발 그리드, 마지막 랩 · 결승선)의 최소 유지 시간을 무시할지. 무시하지 않음(가안 기본) 또는 무시함. 추천 없음(Q-27).

### 5.2 복귀 대상 (가안)

```text
대상 = 유효 요청 중에서
  (1) 우선순위가 가장 높은 것
  (2) 같으면 사건 시각이 이른 것
  (3) 같으면 대표 차 번호가 낮은 것
유효 요청이 없으면 대상 = 기본 화면
```

| 변수 | 뜻 | 범위 | 출처 / 가안 |
|---|---|---|---|
| 유효 요청 | 복귀 시점에 유효 시간 안에 있는 요청 | 0개 이상 | §5.4 |
| 요청 우선순위 | 요청한 장면의 우선순위 | 정수 0~11 | §3.2 |
| 사건 시각 | 요청을 만든 사건의 시각(초) | 0 이상 | §3.6 틱 × 틱 길이 |
| 대표 차 번호 | 관련 차 중 가장 작은 번호 | 정수 0 이상 | §3.6 |

- 결과 범위: 대상은 유효 요청 중 하나이거나 "기본 화면"이다.
- 계산 예시: 세 요청이 있다.
  - 요청 가: 접촉, 대표 차 3, 우선순위 7, 사건 시각 40.0 s
  - 요청 나: 접촉, 대표 차 1, 우선순위 7, 사건 시각 40.0 s
  - 요청 다: 추월, 대표 차 1, 우선순위 5, 사건 시각 38.0 s
  - 우선순위 7이 가와 나 둘이다. 사건 시각이 같으므로(40.0 s) 대표 차 번호가 낮은 나(차 1의 접촉)를 고른다. 요청 다(우선순위 5)는 대상이 되지 않는다.
  - 요청 가는 남은 유효 시간 동안 남지만, 현재 장면(우선순위 7)과 같으므로 끼어들지 못하고 만료된다.
- 퇴화 결과:
  - 유효 요청이 없음: 기본 화면으로 간다.
  - 같은 틱, 같은 차, 같은 종류의 요청이 여러 개이고 모든 필드가 같음: 한 개로 합친다(중복 제거). 필드가 하나라도 다르면 별개로 본다.

### 5.3 미리 당김 (가안)

```text
장면 시작 시각 = max(0, 사건 시각 − 미리 당김)
```

| 변수 | 뜻 | 범위 | 출처 / 가안 |
|---|---|---|---|
| 사건 시각 | 사건이 일어난 시점(초) | 0 이상 | §3.6 틱 × 틱 길이 |
| 미리 당김 | 사건보다 앞서 시작하는 시간(초) | 0~2.0 s | §8 가안 |
| 장면 시작 시각 | 장면이 실제로 시작하는 시점(초) | 0 이상 | 계산값 |

- 결과 범위: 장면 시작 시각은 0 이상이다.
- 계산 예시: 사건 시각 12.0 s, 미리 당김 1.0 s이면 장면 시작 시각은 11.0 s다.
- 퇴화 결과:
  - 미리 당김이 사건 시각보다 큼: 0으로 자른다. 예: 사건 시각 0.5 s, 미리 당김 1.0 s이면 max(0, −0.5) = 0 s.
  - 미리 당김 = 0: 사건 시각에 바로 시작한다.
  - 미리 당김 < 0: 입력 오류. 음수는 허용하지 않는다.

### 5.4 요청 유효 시간 (가안)

```text
요청은 유효하다 = (현재 시각 − 사건 시각 ≤ 유효 시간)
```

| 변수 | 뜻 | 범위 | 출처 / 가안 |
|---|---|---|---|
| 현재 시각 | 판정하는 시점(초) | 0 이상 | 재생 시간 |
| 사건 시각 | 요청을 만든 사건의 시각(초) | 0 이상 | §3.6 |
| 유효 시간 | 요청이 남아 있는 시간(초) | 0~3.0 s | §8 가안 |

- 결과 범위: 유효 또는 버림.
- 계산 예시: 사건 시각 40.0 s, 유효 시간 1.0 s. 현재 시각 41.0 s이면 1.0 ≤ 1.0이므로 유효하다. 현재 시각 41.1 s이면 1.1 > 1.0이므로 버린다.
- 퇴화 결과:
  - 유효 시간 = 0: 현재 시각 = 사건 시각인 틱에만 판정한다(같은 틱만 유효).
  - 유효 시간 < 0: 입력 오류.
  - 고정 중에 온 요청: 유효 여부와 관계없이 버린다(§6).

### 5.x 공통 퇴화 결과

| 상황 | 결과 |
|---|---|
| 최소 유지 시간 = 0 | 계산에는 하한 0.5 s를 쓴다(§8). 설정 기록에는 0을 그대로 남긴다 |
| 최대 유지 시간 < 최소 유지 시간 | 입력 오류. 연출 설정을 거부한다 |
| 재생 시간 ≤ 0(M-10 계산 시) | 계산하지 않고 입력 오류로 기록한다(§9.2) |

- 음수 시간 값은 §5.1–§5.4 각 공식의 입력 오류 규칙을 따른다. 여기서 따로 정하지 않는다.
- 시간 기준(§8 선택지): A안은 시뮬 틱(재현에 유리하고 같은 틱 비교가 정확하다). B안은 재생 초(배속과 연동. 선행 초안 `design_ssot/drafts/RACE_UNIT_LENGTH_CAMERA_P0_DRAFT.md:109–123`). 1배에서는 틱과 초가 1:1로 대응하므로, 두 기준의 판정 결과가 같아야 한다(검증 항목). 추천 없음(Q-15).

## 6. Edge case

| 상황 | 결과 |
|---|---|
| 같은 틱에 사건이 여럿 온다 | §5.2 순서로 고른다(우선순위 높은 것, 같으면 대표 차 번호 낮은 것). 선택되지 않은 사건은 유효 시간 동안 남지만, 선택된 장면과 우선순위가 같거나 낮으면 끼어들지 못하고 만료된다 |
| 고정 중에 사건이 온다 | 버린다(A안 기준). 사건 기록에는 남는다. 연출 기록에 "고정 중 버림"으로 표시한다 |
| 고정을 끈 직후 유효한 요청이 있다 | 다음 틱에 §5.1로 판정한다. 기본 화면이므로 현재 우선순위는 0이다 |
| 내 차가 순위표나 정보 텍스트 영역에 가려진다 | 내 차 중심이 UI 영역에 들어가면 카메라가 내 차를 UI 밖 중앙 영역으로 옮긴다. 옮길 수 없으면 UI 투명도를 0.3으로 낮춘다(가안). 처리 방식은 Q-20 |
| B안 순위표에서 내 차가 상위 3대 안에 있다 | 같은 행을 뺀다. 예: 내 차 2위이면 1, 2, 3위 3행만 표시한다 |
| B안 순위표에서 내 차가 10위다 | 1, 2, 3, 9, 10위 5행을 표시한다 |
| 동순위가 있다 | 시뮬레이터의 순위 정의를 따른다(Q-17). 정의가 생기기 전에는 이 문서에서 정하지 않는다 |
| 리타이어가 일어난다 | 현재 사건 종류에 없으므로 기록하지 않는다. 추가 여부는 Q-18 |
| 결과 상태에서 사건이 온다 | 무시한다(종료 상태) |
| 내 차가 완주한다(고정 중이든 아니든) | §4 규칙에 따라 결과로 간다. 최소 유지 시간과 우선순위를 보지 않는다 |

- 포착 판정: 사건 시각 전후 포착 창 동안 매 틱, 관련 차 전부가 연출 기록에서 "화면 안"이어야 포착이다. "UI에 가려짐"과 "화면 밖"은 포착이 아니다.

- 자동 집계: §3.6 연출 기록(차 위치, 원인 표시)과 사건 기록(대상, 묶음 키)만으로 한다.
- 계산 예시(가상 입력): 대상 10묶음 중 7묶음 포착 → 0.7.

M-10 분당 전환 횟수(가안)
- 식: M-10 = 자동 전환 횟수 ÷ (재생 시간(초) ÷ 60). 자동 전환은 끼어들기와 복귀를 합한다.

- 계산 예시(가상 입력): 자동 전환 6회, 재생 75 s → 6 ÷ 1.25 = 4.8회/분.

M-11 원인 질문 정답 여부(가안)
